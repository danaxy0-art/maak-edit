# Ma’ak — النسخة المطوّرة

مشروع Flutter كامل مبني على ملفات مشروعك الأصلية. اللوغو الأصلي في
`assets/images/logo.png` محفوظ دون تغيير. الواجهات باللغة الإنجليزية كما في المعاينة.
الألوان كحلية وكريمية، مع خلفيات تلال مرسومة، بطاقات بيضاء وأزرار متدرجة.
تصميم الصور مرجع بصري؛ ترتيب النصوص قد يتكيف مع حجم الشاشة وتكبير الخط.

## التشغيل على جهازك

1. ثبتي Flutter **3.35 أو أحدث**، وافتحي هذا المجلد في VS Code.
2. افتحي مشروع Supabase الذي تستخدمينه، ثم SQL Editor.
3. انسخي محتوى **supabase_schema.sql كاملًا** وشغليه. الملف يضيف الجداول والصلاحيات
   ويحتفظ ببيانات الحسابات الموجودة. شغليه كاملًا داخل المعاملة كما هو.
4. في Authentication → Email Templates اجعلي قالب **Confirm signup** وقالب
   **Reset Password** يحتويان على `{{ .Token }}` ليصل رمز تحقق إلى البريد.
   تحققي من إعداد SMTP الموجود في مشروعك ومن وصول الرسائل. لا يلزم تعطيل تأكيد البريد.
5. من Terminal داخل مجلد المشروع:

```bash
flutter pub get
flutter analyze
flutter test
flutter run
```

اتصال Supabase الأصلي موجود كقيمة افتراضية للمحافظة على مشروعك، ويمكن تغييره عند التشغيل:

```bash
flutter run --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_KEY
```

المفتاح المطلوب هو Publishable / anon فقط. لا تضعي Service role أو Secret key في التطبيق.

## حساب الإدارة

سجلي حسابًا عاديًا وحققي البريد. داخل **SQL Editor فقط** عيّني حساب الإدارة:

```sql
update public.profiles
set role = 'admin'
where id = (select id from auth.users where email = 'YOUR_ADMIN_EMAIL');
```

سجلي خروجًا ثم ادخلي بهذا الحساب. تظهر لوحة الإدارة وطلبات المتطوعين وإدارة الحالات.
الحسابات لا تستطيع تغيير دورها إلى admin من التطبيق.

## ربط البيانات

- التسجيل يحفظ الملف وتفضيلات الدعم في عملية قاعدة بيانات واحدة بعد تحقق البريد.
  إذا أغلقتِ التطبيق بعد إنشاء الحساب وقبل إكمال التفاصيل، يعرض تسجيل الدخول شاشة إكمال الملف.
- طلب المتطوع يبقى pending_review حتى قرار الإدارة؛ عند رفضه يمكن تعديل الطلب وإعادة تقديمه.
- مستندات التحقق في مجلد خاص، بحد 5 MB وصيغ PDF / PNG / JPG. يفتحها صاحبها والإدارة فقط.
- المتطوعون في البحث هم المعتمدون فعليًا. طلب الدعم يُحفظ، ثم يقبله أو يرفضه المتطوع.
- تظهر المحادثة بعد قبول الطلب. الرسائل محفوظة في messages، مع تحديث مباشر وإشعار للطرف الآخر.
- يستطيع المتطوع تحديد جلسة مع شخص متصل به؛ يمنع الموعد الماضي وتداخل الجلسات.
  هذا تنظيم لموعد الدعم، ولا يحتوي على مكالمات فيديو.
- My journey يعرض طلبات الدعم الفعلية وحالتها. لا توجد محادثات أو أسماء تجريبية في التطبيق.
- Resources يعرض البيانات المنشورة في جدول resources؛ يبدأ فارغًا حتى تضيفي المحتوى.

يمكن للإدارة نشر مصدر من SQL Editor:

```sql
insert into public.resources(title, summary, url)
values ('YOUR_TITLE', 'YOUR_SUMMARY', 'https://YOUR_RESOURCE_URL');
```

## هيكلة الملفات

- `lib/frontend/redesign/`: عناصر التصميم وشاشات التسجيل والرئيسية والإدارة والملفات والدعم.
- `lib/frontend/theme/app_theme.dart`: الألوان وأحجام الحقول والبطاقات والأزرار.
- `lib/frontend/widgets/maak_logo.dart`: عرض ملف لوغوك الأصلي.
- `lib/backend/services/supabase_service.dart`: ربط Supabase وعمليات التطبيق.
- `lib/backend/validation/`: التحقق من كلمة المرور والحقول.
- `supabase_schema.sql`: إنشاء / ترقية قاعدة البيانات والصلاحيات ودوال الحفظ.
- `test/`: اختبارات تحقق الحقول وكلمة المرور والرفض داخل النافذة.
- `tests/database/`: اختبارات قاعدة البيانات مع PostgreSQL محليًا داخل PGlite، دون الاتصال بمشروعك.
- `VALIDATION.md`: نتائج الفحوص وما يحتاج تجربة على حساباتك وجهازك.

هذه النسخة لم تُشغّل SQL داخل مشروع Supabase الخاص بك ولم تنشئ حسابات فيه.
يلزم تنفيذ خطوات الإعداد أعلاه لتعمل الشاشات المتصلة بالبيانات.


## تحديث إعدادات Android
هذه النسخة تستخدم Gradle 8.14.3 وAndroid Gradle Plugin 8.11.1 وKotlin 2.2.20، وفق الحد الأدنى الذي ظهر في سجل Flutter لديك. بعد فك الضغط في مجلد جديد، نفّذي `flutter pub get` ثم `flutter run -d emulator-5554`. لا تنقلي ملف `android/local.properties` من جهاز آخر. قد تبقى تحذيرات التحديث المستقبلي للإصدارات؛ تم تعديل الإصدارات التي سببت أخطاء التحقق الحالية. لم يُختبر بناء Android داخل بيئة التسليم.


## تحديث وضوح الأخطاء وتوقيت التحقق
حقول النص تتحقق بعد الخروج من الحقل أو إرسال النموذج، وتظهر رسالة واضحة فوق الحقل بإطار أحمر. الحقول الأخرى لا تتأثر بالكتابة في خانة واحدة. قائمة شروط كلمة المرور تبقى مباشرة أثناء الكتابة. الأخطاء العامة تظهر في نافذة وسط الشاشة مع إغلاق وإعادة المحاولة بدل تنبيه أسفل الشاشة. شكل القوائم ورسائل رفع المستندات والإدارة موحد. شريط أدوات لوحة المفاتيح الظاهر في صور Android يتحكم فيه نظام الجهاز.
إذا تعذّر تحميل الأمراض، تأكدي من تنفيذ `supabase_schema.sql` في مشروع Supabase المتصل بالتطبيق وفق تعليمات الإعداد؛ لم نطبّق ترحيل قاعدة البيانات على حسابك.


## النسخة النباتية
جميع الصفحات تستخدم الآن التصميم النباتي بدون أشخاص. الصور والخطوط مضمّنة في مجلد assets، ولا تحتاجين تنزيلها يدويًا. الحقول والأزرار فعلية وليست صورًا. تفاصيل التصميم ومعاينات Flutter في DESIGN_GUIDE_AR.md وtest/goldens. صفحة التسجيل طويلة في الخطوة الأولى وقابلة للتمرير، ويمكن العودة من التفضيلات بالضغط على Account بالأعلى. احتُفظ بإعدادات Android المحدثة وسلوك الأخطاء بعد الخروج من الحقل أو الإرسال.
